# Interval Lab 1.3.0

Мобильное веб-приложение с двумя режимами секундомера, независимыми парами попыток нескольких спортсменов на **одном устройстве**, историей и ручным вводом архивных результатов. Интерфейс на русском языке. Без внешних JS-библиотек, сервера и учётных записей.

## Выбор режима

В верхней панели экрана измерения нажмите значок режима (слева от «История»), затем выберите:

**1. С промежуточными отсечками.** При N=10 интервалах нужно 11 касаний: первое запускает часы и показывает крупное `0`, последующие фиксируют 10 интервалов, увеличивая цифру до `10`. Последнее автоматически завершает попытку. Результат включает общее время и таблицу/график интервалов. Число интервалов настраивается от 1 до 200.

**2. Только Старт–Стоп.** Отдельный экран с **крупным временем**, без счётчика отсечек, таблицы и графика интервалов. Первое касание запускает часы, второе останавливает. Сохраняется только общее время попытки.

Оба режима используют монотонные часы `performance.now()`, подтверждают каждое **принятое** касание контрастной янтарной вспышкой на **150 мс** и игнорируют повторные касания через **1000 мс или раньше** после последнего принятого. На завершённом экране измерения результат остаётся виден на 650 мс, затем открывается анализ. Выбор режима доступен **до начала каждой попытки**, включая вторую попытку одной пары; во время измерения режим переключить нельзя.

## Две попытки и лучший результат

Каждая завершённая пара содержит **две попытки** одного спортсмена. Для сравнения используется **минимальное общее время** из двух, независимо от режима каждой попытки. Внутри пары могут быть разные режимы. Если попытка выполнена с отсечками, её интервалы сохраняются в дополнительных деталях; для сравнений лучших времён детализация **не нужна**. Одна незавершённая попытка ещё не образует «лучший из двух» и не участвует в долгосрочном сравнении.

**Несколько спортсменов:** можно измерять последовательность A1 → B1 → A2 → B2. На экране профилей добавляют, выбирают, переименовывают и удаляют спортсменов. Незавершённые пары и история принадлежат отдельным спортсменам; физически измеряется одна попытка за раз. Отсчёт паузы между попытками каждого спортсмена учитывает всё прошедшее время, включая выполнение упражнения другим спортсменом. Профили — локальные ярлыки, а не аккаунты и не ограничения доступа.

## Ручной архив

Перейдите в **История** для выбранного спортсмена и заполните форму **«Добавить архивный результат»**:

- Дата упражнения в формате календарной даты.
- **Лучшее общее время** в секундах, например `12,345` или `12.345` (точность до миллисекунд).

Архивная запись не создаёт фиктивных попыток или промежуточных отсечек. Она участвует в хронологии и сравнении с завершёнными двухпопыточными парами. Записи можно удалить с подтверждением; при удалении спортсмена удаляются его пары и архивные записи.

## Аналитика

- В результате пары отображаются времена обеих попыток, **лучшее время** и пауза между попытками.
- В режиме с отсечками дополнительно доступны график и таблица интервалов (сравнение интервалов только для попыток, где они измерялись).
- Сравнение с историей использует **только лучшее общее время** предыдущей завершённой пары либо вручную внесённую архивную запись выбранного спортсмена. Отрицательная разность означает улучшение.
- История отделена по спортсменам, в неё входят измеренные пары и архивные записи; по одной только попытке итог пары не вычисляется.

## Хранение, резервные копии и обновление

Все измерения и профили находятся в `localStorage` **этого браузера на этом устройстве**. На GitHub загружаются только исходники приложения; личные результаты автоматически никуда не отправляются и между устройствами не синхронизируются.

Экспорт JSON создаёт резервную копию со всеми спортсменами, исходными попытками, режимами, интервалами и вручную введёнными архивными результатами. Импорт поддерживает **v1, v2, v3**, проверяет целостность и объединяет записи по ID без дублирования; CSV содержит и измерения, и архивные лучшие времена. **Перед обновлением экспортируйте JSON.**

Хранилище использует прежний ключ `interval-lab:data:v1`, но новая нормализованная структура — `version:3`. При открытии прежней истории форматов v1/v2 старая история конвертируется в формат v3 без изменения времён интервалов и принадлежности спортсменам. Формат v2 продолжает связывать старые упражнения со спортсменами, формат v1 — с профилем «Спортсмен 1». **После обновления до 1.3.0 версии 1.1/1.2 не смогут прочитать обновлённое хранилище v3**, поэтому возврат требует резервной копии прежней версии.

## Установка и автономная работа

Для локального запуска распакуйте `interval-lab_1.3.0.zip`, перейдите в каталог `interval-lab` и запустите:

```sh
python3 -m http.server 8000
```

Откройте `http://localhost:8000`. На смартфоне в локальной сети используйте IP компьютера (доступ/разрешения зависят от сети). Секундомер работает по локальному HTTP; Service Worker и Wake Lock на незашифрованном HTTP по IP могут быть недоступны. Открытие файла через `file://` не гарантирует сохранность `localStorage`.

Для GitHub Pages приложение размещается по пути `t39s/dev-sandbox/interval-lab/`. Если GitHub Pages публикует `main` из корня репозитория, адрес: `https://t39s.github.io/dev-sandbox/interval-lab/`. Чтобы использовать PWA офлайн, сначала откройте сайт по HTTPS с доступом к сети и дождитесь успешной установки Service Worker. После первой загрузки оболочка кешируется, а история по-прежнему остаётся в `localStorage`.

## Ограничения

- Это измерение с точностью времени браузера, а не сертифицированный хронометр. Влияние оказывают задержки сенсорного ввода и активность вкладки.
- Для предотвращения двойного нажатия интервал между **двумя принятыми касаниями должен быть строго больше одной секунды**. Поэтому попытку «Старт–Стоп» длительностью не больше секунды измерить нельзя в текущей конфигурации.
- Незавершённая **попытка** теряется при перезагрузке, но полностью завершённая первая попытка пары сохраняется и может быть продолжена позднее.
- Удаление локальных данных, приватный режим, смена браузера или устройства могут уничтожить историю; используйте экспорт JSON.

## Проверки

```sh
node --test tests/*.test.cjs
python tests/browser_check.py
python tests/browser_athletes_check.py
python tests/browser_modes_archive_check.py
```

Автоматизированные тесты охватывают модель данных, миграцию v1/v2, ввод архива, импорт и защиту от конфликтов, смешанные режимы, 11 нажатий для 10 интервалов, строгий порог 1000 мс и независимые пары A1/B1/A2/B2. Браузерные сценарии выполняются в Chromium (Playwright). В доступном тестовом окружении HTTP-навигация браузера может блокироваться администратором: в таком случае исходники инжектируются в DOM. Это проверяет браузерное отображение и интерфейс, но **не подтверждает** HTTP-публикацию, Service Worker или реальное офлайн-использование.
