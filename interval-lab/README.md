# Interval Lab 1.4.2

Мобильное автономное веб-приложение для интервального измерения времени и режима «Старт–Стоп» с локальной историей нескольких спортсменов на **одном устройстве**. Язык интерфейса — русский. Регистрация и серверная база данных не требуются.

## Конфигурация защиты от повторных нажатий (1.4.2)

Измените файл `config.json` в каталоге приложения:

```json
{
  "minTapGapMs": 500
}
```

Параметр `minTapGapMs` — **минимальный интервал блокировки повторного принятого нажатия в миллисекундах**. Если прошло **не более** заданного значения, новое нажатие игнорируется и не сбрасывает отсчёт защитного интервала. Только при строго большем интервале оно принимается и фиксирует отсечку либо останавливает режим «Старт–Стоп». Например, для 500 мс: через 400 и 500 мс — игнорируется, через 501 мс — принимается. Первое нажатие запускает секундомер сразу после успешной загрузки конфигурации.

Допускается только целое число от **0 до 60 000** мс. При ошибке чтения, некорректном JSON или недопустимом значении старт блокируется с сообщением на экране; скрытой подстановки запасного значения нет. Значение читается **при загрузке страницы** и фиксируется на всю текущую попытку. Для изменения параметра отредактируйте файл и перезагрузите приложение. Файл `config.json` входит в офлайн-кэш PWA. При локальном запуске требуется HTTP-сервер (см. ниже); открытие `index.html` напрямую по `file://` не поддерживает надёжное чтение конфигурации.

Параметр относится только к фильтрации касаний, а не к физическому времени измеренных интервалов. Значение не записывается в JSON-историю и не синхронизируется между устройствами. Для сопоставимости экспериментов сохраняйте вместе с экспортом истории использованную редакцию `config.json`.

## Основной сценарий

**Изменения 1.4.1:** до первого касания основной счётчик показывает `0` вместо огромного тире. Удалены текст очередного нажатия справа и блок «Последний интервал» снизу. Крупный счётчик, общее время, шкала прогресса и вся аналитика сохранены.


В интерфейсе **«С отсечками»** первое касание запускает секундомер и отображает большой `0`. Следующие N касаний фиксируют N интервалов. При настройке N=10 это 11 касаний и крупная цифра от `0` до `10`. Последнее касание автоматически завершает попытку.

**Старт–Стоп** — самостоятельный интерфейс с крупным временем. Первое касание запускает, второе останавливает. Промежуточные отсечки не отображаются и не создаются.

В обоих режимах принятое касание подтверждается контрастной вспышкой на 150 мс. Повторное касание принимается только при времени **строго более `minTapGapMs`** с момента предыдущего принятого касания (в текущей конфигурации 500 мс). Режим можно выбрать перед каждой попыткой. Непрерывность измерения основана на `performance.now()`.

## Серии, спортсмены, рейтинг

Для каждого спортсмена допускается **серия из двух зачётных попыток**. Их режимы могут различаться. В длительном сравнении используется **минимальное общее время** завершённой серии, без требования интервалов. Первая попытка остаётся сохранённой при переключении спортсмена; поддерживается порядок A1 → B1 → A2 → B2.

**Новое: отказ от второй попытки.** После первой завершённой зачётной попытки на странице результата есть кнопка «Завершить серию без второй попытки». После подтверждения серия получает статус «Завершена», её лучшим временем становится время первой попытки, и она участвует в истории и сравнении. Серия другого спортсмена остаётся независимой. Возобновить вторую попытку после подтверждённого отказа нельзя; следующая попытка начинает новую серию.

**Новое: досрочное завершение в режиме с отсечками.** Во время измерения доступна отдельная кнопка **«Завершить досрочно»**, расположенная за пределами области регистрации отсечек. После подтверждения измерение останавливается. Сохраняются фактическое время до остановки и уже измеренные интервалы (возможно ноль), плановое число интервалов и спортсмен. Запись имеет статус **«Неполная попытка»**, показывается в истории и доступна для просмотра отсечек. Она **не участвует в рейтинге**, **не занимает слот** одной из двух зачётных попыток и позволяет повторить ту же попытку. Кнопка не используется в режиме «Старт–Стоп».

## История и архив

Для каждого спортсмена доступны три типа записей:

- **Автоматическая серия** — одна или две зачётные попытки, итоговое лучшее время; открывается подробный анализ.
- **Неполная попытка** — досрочно завершённое измерение с фактическим временем и сохранёнными отсечками, без зачёта.
- **Ручной архив** — дата и лучшее общее время, без фиктивных отдельных попыток и интервалов.

**Новое: точечное удаление.** Для каждого из трёх типов записей в истории есть отдельная кнопка удаления с обязательным подтверждением. Удаляется лишь выбранная запись конкретного спортсмена. Сравнение и последующие JSON/CSV-экспорты используют оставшиеся данные. Удаление необратимо в текущей истории; однако **импорт старой резервной копии может вернуть удалённые записи**, поскольку импорт объединяет данные по идентификаторам.

## Данные и обновление

Все данные хранятся в `localStorage` текущего браузера. Они не передаются в GitHub и не синхронизируются между устройствами. JSON-экспорт содержит все профили, закрытые и ожидающие продолжения серии, все режимы, ручные архивные записи и неполные попытки. CSV содержит времена и отметки статусов, но у неполных попыток поле лучшего результата пустое.

Хранилище сохраняет ключ `interval-lab:data:v1`. Новый формат — `version: 4`; при запуске версия 1.4.2 автоматически **мигрирует форматы v1, v2 и v3** в v4, сохраняя измерения. Старые незавершённые серии остаются незавершёнными. Ранее завершённые серии из двух попыток остаются зачётными. Программа импорта принимает JSON v1–v4; одинаковые идентификаторы проверяются на конфликты.

**Перед обновлением экспортируйте JSON в настройках.** Старые выпуски 1.1–1.3 не смогут читать новое хранилище v4 после миграции.

## Запуск

Скачайте ZIP, распакуйте и в каталоге `interval-lab` выполните:

```sh
python3 -m http.server 8000
```

Откройте `http://localhost:8000` на том же устройстве или используйте доступный локальный сервер. На смартфоне по IP-адресу без HTTPS сервисный работник и Wake Lock могут быть недоступны.

Путь GitHub: `t39s/dev-sandbox/interval-lab/`. Если GitHub Pages публикует `main` из корня репозитория, веб-адрес: `https://t39s.github.io/dev-sandbox/interval-lab/`. Успешная доступность этого адреса требует отдельной проверки. Оболочка PWA может кэшироваться для офлайн-работы после первого успешного HTTPS-открытия; история по-прежнему остаётся только на устройстве.

```sh
node --test tests/*.test.cjs

```

Выпуск 1.4.0 проверялся автоматическими и браузерными сценариями на экранах 390×844 и 320×568. Регрессионные проверки 1.4.2 дополнены сценариями настраиваемого порога, недопустимой конфигурации и асинхронного запуска. Браузерное выполнение на физическом смартфоне отдельно не подтверждено. В тестовой среде браузерная HTTP-навигация может блокироваться, поэтому используется внедрение HTML/CSS/JS в DOM; это **не** подтверждает доступность GitHub Pages или реальное поведение Service Worker на телефоне. Точность измерений ограничена временем реакции пользователя, задержками сенсорного ввода и планированием браузера. Активная попытка при перезагрузке страницы не восстанавливается; сохранённые результаты сохраняются.
