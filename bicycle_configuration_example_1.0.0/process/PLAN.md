# План продуктового цикла

## Scope

Создать учебный комплект 1.0.0 по постановке OWNER_GOAL 1.0.0. Сохранить её десять критериев, русский язык, крупный масштаб и пять основных развилок. Реальный GitHub-репозиторий не публиковать; это не требуется постановкой.

## Целевое изменение

От постановки цели перейти к законченной истории, которую можно читать без Git, и к проверяемой локальной истории Git для практического разбора.

## Решения по устройству комплекта

- Основной маршрут: README → LESSON → PRACTICE.
- Локальный Git-репозиторий передаётся одним bundle с ветками и тегами; snapshot позволяет читать текущие файлы без клонирования.
- Три участника сюжета: владелец сценария, конструктор, сборщик. Один человек может совмещать роли; изменение проверяет другой участник.
- Требования, описания узлов, свидетельства и запись экземпляра имеют разные назначения. Учебные карточки PR размещены в рассказе; отдельные ADR и журналы согласований не вводятся.
- Выпуск на изготовление относится к одному опытному экземпляру и ограниченной программе проб, а не к серийному допуску.
- После принятия новой проектной версии запись о реально установленной трансмиссии меняется отдельным событием обслуживания.

## Проверки

Провести ревью по десяти критериям постановки. Проверить арифметику передач и бюджета, наличие всех веток и тегов, происхождение параллельных веток, чистое слияние несовместимого предложения, отказ проверки и успех после исправления. Проверить разные состояния экземпляра до и после обновления проекта. Клонировать bundle и проверить соответствие snapshot его main. Проверить локальные ссылки и целостность ZIP.

Проверки интерфейсов являются узкими проверками учебной модели. Они не доказывают физическую работоспособность велосипеда.

## Риски и артефакты

Риски: слишком много документации; вымышленный PR воспринимается как реальный; Git merge воспринимается как физическое изготовление; новые проектные данные подменяют историю экземпляра. Для каждого риска предусмотрены пояснение и проверяемая сцена.

Артефакты: основной рассказ, практикум с ответами, исходная постановка, snapshot, Git bundle, индекс реальных commit ID, проверочный скрипт и отчёт, краткие документы цикла. Документы process относятся к работе над учебным продуктом и не предлагаются как обязательная бюрократия велосипедной команды.

Граница STOP: десять критериев выполнены, нарушающих их находок не осталось, комплект проверен и доступен пользователю. Следующий цикл нужен только при выявленном разрыве внутри этой цели.
