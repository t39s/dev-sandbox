# История версий ttt

## 0.5.0

Объединены три разработанных варианта игры в одном минималистичном интерфейсе.

### Режимы

- `3×3 / 3 подряд` — точный алгоритм; лучший результат пользователя при совершенной игре — ничья.
- `4×4 / 4 подряд` — Alpha–Beta с исходной эвристикой версии `0.3.0`.
- `4×4 / 3 подряд` — точный алгоритм; X имеет форсированную победу.

### UI

- Добавлен сегментированный native-radio переключатель режимов.
- Размер поля и условие победы видны одновременно.
- Отдельный экран настроек не используется.
- Поле динамически строится из 9 или 16 клеток.
- Счёт показывает только релевантные метрики текущего режима.
- Последний выбранный режим сохраняется в `ttt_selected_mode_v1`.
- Пояснения режимов сокращены для стабильной мобильной компоновки.

### Архитектура

- Добавлен `modes.js` — единый каталог режимов.
- `game-model.js` стал универсальным для произвольной пары `boardSize / winLength` в поддерживаемом диапазоне.
- `ai-model.js` маршрутизирует `exact` и `alpha-beta` без копирования контроллера игры.
- Сохранены прежние ключи статистики каждого режима.

### Ревью и доработка

- Обнаружено и исправлено скрытое изменение весов эвристики `4×4 / 4` при обобщении кода.
- Восстановлены исходные веса `[0, 2, 18, 180, 20 000]`.
- Добавлено запоминание выбранного режима без новых элементов интерфейса.
- Проведён реальный headless Chromium smoke-test на мобильном viewport `390×844`.

### Проверка

- Автоматические тесты: **27/27 успешно**.
- `3×3`: алгоритм не проигрывает ни при одной последовательности ходов пользователя.
- `4×4 / 3`: подтверждены все 16 проигрышных для O позиций после первого хода X.
- `4×4 / 4`: сохранены исходная эвристика, глубины поиска и тактическая блокировка.
- Переключение режима отменяет ожидающий ход алгоритма.
- Счёт каждого режима загружается независимо.
- Native radio-group проверена клавиатурным переключением в Chromium.

### Документация

- `UI_RESEARCH.md` — исследование аналогичных интерфейсов.
- `PLAN.md` — план объединения.
- `GENERAL_REVIEW.md` — итоговое ревью после доработки.

## 0.4.0

Новые правила: поле остаётся `4×4`, но для победы достаточно **3 последовательных символов**.

### Исследование и планирование

- Полные материалы: `RESEARCH.md`, `PLAN.md`, `AI_STRATEGY.md`.
- Определены 24 выигрышных отрезка длины 3.
- Независимый исчерпывающий поиск установил: первый игрок `X` имеет форсированную победу.
- Прежний эвристический Alpha–Beta заменён на точный полный Minimax с memoization.

### Разработка

- Добавлена константа `WIN_LENGTH = 3`.
- Генератор победных комбинаций строит горизонтальные, вертикальные и обе диагональные ориентации.
- Сохранено поле CSS Grid `4×4`.
- Текст правил обновлён без ложного обещания непобедимости алгоритма.
- Алгоритм выбирает game-theoretically optimal ход.
- Счёт `Вы / Ничьи / Алгоритм` сохранён.
- Новый ключ статистики: `ttt_score_4x4_k3_v1`.

### Ревью и доработка

Первый прогон выявил, что чистая оценка `win / draw / loss` могла выбирать формально оптимальный, но визуально слабый ход при неизбежном поражении.

Исправлено:

- добавлен приоритет собственной немедленной победы;
- добавлена обязательная блокировка немедленной угрозы;
- те же тактические факты используются для безопасного pruning полного поиска;
- добавлен доказанный легальный сценарий ничьей;
- ускорен независимый proof-test без использования production solver.

Полное ревью: `GENERAL_REVIEW.md`.

### Проверка

- `node --check` для JavaScript — успешно.
- Автоматические тесты: **28/28 успешно**.
- Проверены все 24 уникальных выигрышных отрезка:
  - 8 горизонтальных;
  - 8 вертикальных;
  - 4 диагонали `↘`;
  - 4 диагонали `↙`.
- Проверена легальная 16-ходовая ничья.
- Два независимых решателя подтверждают форсированную победу X.
- После каждого из 16 возможных первых ходов X позиция O имеет game-theoretic value `loss`.
- Точный поиск всех 16 первых ответов укладывается в performance-бюджет.
- Проверены HTML/CSS 4×4, UI-flow, accessibility-состояния и независимый ключ счёта.

## 0.3.0

Версия переводит игру «пользователь против алгоритма» с поля 3×3 на классическое поле 4×4.

### Исследование

- Зафиксированы правила 4×4: 16 клеток, `X` ходит первым, победа по четырём символам в полной строке, столбце или диагонали.
- Для поля определены 10 выигрышных линий: 4 горизонтали, 4 вертикали, 2 диагонали.
- Полный Minimax 3×3 признан неподходящим для прямого переноса на раннюю стадию 4×4 из-за роста дерева поиска.
- Выбран Alpha–Beta Minimax с ограниченной глубиной, эвристикой и полным поиском поздней игры.
- Результаты исследования сохранены в `RESEARCH.md` и `AI_STRATEGY.md`.

### Планирование

- Создан `PLAN.md` с этапами: модель → AI → UI/UX → счёт → тесты → ревью.
- Для новой игры введён отдельный счёт, чтобы не смешивать статистику 3×3 и 4×4.

### Разработка

- `BOARD_SIZE` изменён на 4, поле — на 16 клеток.
- Выигрышные комбинации формируются программно.
- UI переведён на CSS Grid 4×4.
- Доступные имена клеток используют координаты `строка / столбец`.
- Сохранены подсветка последнего хода, выигрышной линии, `aria-disabled` и `aria-busy`.
- Счёт содержит `Вы / Ничьи / Алгоритм`.
- Новый ключ хранения: `ttt_score_4x4_v1`.
- Результаты 3×3 в новую статистику не переносятся.

### AI

- Реализован Alpha–Beta Minimax.
- Перед поиском алгоритм всегда проверяет:
  - собственную победу в один ход;
  - необходимость блокировки победы пользователя в один ход.
- Добавлена эвристика открытых выигрышных линий.
- Добавлено стабильное упорядочивание ходов для улучшения отсечений.
- Глубина адаптируется к числу свободных клеток.
- При 9 и менее свободных клетках выполняется полный поиск до конца партии.
- В ранней игре AI не заявляется математически совершенным.

### Ревью и доработка

После первой реализации проведено отдельное общее ревью.

Исправлено:

- порог полного поиска повышен с `≤8` до `≤9` после анализа чётности ходов и benchmark;
- магическое число `4` в UI-контроллере заменено на `BOARD_SIZE`;
- добавлены тесты статической HTML/CSS-структуры 4×4;
- performance-проверка расширена на все 16 возможных первых ходов пользователя.

Полный результат ревью: `GENERAL_REVIEW.md`.

### Проверка

- `node --check` для JavaScript — успешно.
- Автоматические тесты: **25/25 успешно**.
- Проверены все 10 выигрышных линий и валидная ничья.
- Проверены немедленная победа и блок AI.
- Проверены все 16 вариантов первого хода пользователя в performance-бюджете.
- Проверены 16 уникальных клеток HTML и CSS Grid 4×4.

## 0.2.2

Версия подготовлена по результатам общего ревью `0.2.1`.

### Исправлено — продуктовая согласованность

- Удалена недостижимая метрика побед пользователя из счёта серии.
- Режим теперь явно сообщает, что алгоритм играет без ошибок.
- Цель пользователя сформулирована как `добиться ничьей`.
- Счёт интерфейса упрощён до `Ничьи / Алгоритм`.
- При ничьей статус сообщает `Ничья — цель достигнута`.

### Исправлено — доступность игрового поля

- Игровые клетки больше не переводятся в HTML `disabled`.
- Для занятых и временно недоступных клеток используется `aria-disabled`.
- Клетки остаются фокусируемыми после хода и во время ответа алгоритма.
- Во время хода алгоритма поле получает `aria-busy="true"`.
- Защита от недопустимого хода остаётся в игровой модели и контроллере.

### Изменена модель счёта

- Схема счёта теперь содержит только:
  - `algorithm`;
  - `draws`.
- Новый ключ `localStorage`: `ttt_score_v3`.
- Добавлена миграция из `ttt_score_v2` с сохранением побед алгоритма и ничьих.
- Старый счётчик `human` при миграции игнорируется.

### Укреплён AI API

- `getOpponent()` безопасно отвергает неизвестного игрока.
- `getAvailableMoves()` безопасно обрабатывает некорректное поле.
- `getBestMove()` проверяет структуру поля и игрока перед поиском.

### Документация

- Добавлен `GENERAL_REVIEW.md` с полным ревью архитектуры, продукта, AI, состояния, UI/UX и тестовой стратегии.

### Проверка

- `node --check` для всех JavaScript-файлов — успешно.
- Автоматические тесты: **30/30 успешно**.
- Исчерпывающая проверка непроигрышности Minimax сохранена.
- Добавлены тесты:
  - защитных контрактов AI;
  - двухсчётчиковой модели серии;
  - миграции счёта;
  - `aria-disabled`;
  - `aria-busy`;
  - сохранения клеток в клавиатурной навигации.

## 0.2.0

Продуктовое изменение: режим «пользователь против алгоритма» с совершенной стратегией.

### Исследование

- Для поля 3×3 при совершенной игре обеих сторон гарантированный исход — ничья.
- Поэтому цель алгоритма — не «всегда выиграть», а гарантировать отсутствие поражений и конвертировать ошибки пользователя в победу.
- Выбран Minimax с полным просмотром дерева продолжений. Подробности — `AI_STRATEGY.md`.

### Изменено

- Пользователь всегда играет `X` и ходит первым.
- Алгоритм играет `O` и автоматически отвечает после допустимого хода пользователя.
- Интерфейс счёта изменён на `Вы / Ничьи / Алгоритм`.
- Статусы партии адаптированы к режиму против алгоритма.
- Схема счёта изменена с `X / O / draws` на `human / algorithm / draws`.
- Ключ хранилища изменён на `ttt_score_v2`, чтобы не смешивать результаты прежнего режима двух игроков с новым режимом.

### Добавлено

- `ai-model.js` — независимая от DOM модель алгоритма.
- Minimax с оценкой по глубине и детерминированным разрешением равных оптимальных ходов.
- `AI_STRATEGY.md` — результаты исследования и план реализации.
- Unit-тесты поведения алгоритма.
- Исчерпывающий тест всех последовательностей пользовательских ходов против алгоритма.

### Ревью и исправления

- Ужесточена модель счёта: неизвестный победитель больше не засчитывается алгоритму.
- Удалён лишний промежуточный рендер между ходом пользователя и синхронным ответом алгоритма.
- Полное ревью сохранено в `REVIEW.md`.

### Проверка

- `node --check` для всех JavaScript-файлов — успешно.
- Полный автоматический прогон: **25 тестов, 25 успешно, 0 ошибок**.
- Исчерпывающая проверка политики алгоритма: **521** терминальная ветвь, **0** побед пользователя, **368** побед алгоритма, **153** ничьи.
- Добавлен интеграционный DOM-flow тест: ход пользователя → ответ алгоритма → завершение партии → счёт → новая игра → сброс счёта.

## 0.1.2

Продуктовое улучшение: счёт серии партий.

### Цель

Сделать последовательность партий осмысленной: игроки видят общий результат серии, а счёт сохраняется между перезапусками страницы.

### Изменено

- Добавлена панель счёта: победы `X`, победы `O`, ничьи.
- Кнопка «Новая игра» сбрасывает только текущую партию и сохраняет счёт серии.
- Добавлена кнопка «Сбросить счёт».
- Счёт сохраняется в `localStorage` под ключом `ttt_score_v1`.
- При недоступности или повреждении `localStorage` приложение продолжает работать со счётом `0 / 0 / 0`.

### Архитектура

- Логика счёта вынесена в отдельный `score-model.js`.
- Счёт увеличивается только при переходе игры из `playing` в `won` или `draw`, поэтому один результат не может быть засчитан повторно.
- Данные из хранилища нормализуются перед использованием.

### Тесты

- Добавлены unit-тесты модели счёта: начальное состояние, нормализация, победы `X` и `O`, ничья и незавершённая партия.
- Полный регрессионный прогон: **16 тестов, 16 успешно, 0 ошибок**.
- `node --check` для `game-model.js`, `score-model.js` и `script.js` — успешно.
