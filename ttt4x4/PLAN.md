# План ttt 0.5.0 — единый интерфейс трёх вариантов

## 1. Архитектура

- Ввести `modes.js` как единственный каталог режимов.
- Сделать `game-model.js` параметрическим по `boardSize` и `winLength`.
- Оставить один `score-model.js`.
- Сделать `ai-model.js` маршрутизатором двух стратегий:
  - `exact`;
  - `alpha-beta`.

## 2. UI

- Один экран.
- Сегментированный native-radio переключатель режимов.
- Динамически строить 9 или 16 кнопок поля.
- Динамически менять краткое описание режима.
- Динамически показывать только релевантные счётчики.
- Сохранить последний ход, победную линию, `aria-disabled`, `aria-busy` и подтверждение сброса.

## 3. Совместимость данных

Использовать прежние ключи:

- `ttt_score_v3`;
- `ttt_score_4x4_v1`;
- `ttt_score_4x4_k3_v1`.

Это позволяет объединить интерфейс без потери уже накопленного счёта.

## 4. Тесты

Проверить:

- каталог содержит ровно 3 режима;
- правила дают 8, 10 и 24 выигрышные линии соответственно;
- каждый режим корректно завершает победную партию;
- exact-алгоритм 3×3 не проигрывает;
- exact-алгоритм 4×4/3 сохраняет game-theoretic оптимальность;
- 4×4/4 использует Alpha–Beta и блокирует тактическую угрозу;
- UI строит 9/16 клеток при переключении;
- переключение отменяет ожидающий ход алгоритма;
- счёт загружается из отдельного storage key;
- классический режим скрывает недостижимый счётчик побед пользователя;
- native radio остаётся доступным с клавиатуры.

## 5. Ревью

После первой реализации проверить:

- не перегружен ли экран описаниями;
- достаточно ли различимы два режима 4×4;
- нет ли общего состояния между режимами;
- не возникает ли гонка от отложенного хода при смене режима;
- не ухудшена ли мобильная компоновка;
- нет ли дублирования правил/алгоритмов.
