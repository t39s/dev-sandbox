# Общее ревью — ttt 0.5.0

## Область

Проверены:

- результаты исследования аналогичных UI;
- информационная архитектура трёх режимов;
- минималистичность экрана;
- сохранение поведения трёх ранее разработанных игр;
- универсальная игровая модель;
- маршрутизация алгоритмов;
- раздельный счёт;
- переключение режимов;
- accessibility;
- мобильная компоновка;
- unit/integration tests;
- реальный headless-browser smoke-test.

## Итог первой реализации

Первая реализация успешно объединила три режима в одном экране:

- `3×3 / 3 подряд`;
- `4×4 / 4 подряд`;
- `4×4 / 3 подряд`.

Поле строится динамически и использует одну модель правил. Отдельных копий UI или игровой логики для режимов нет.

Первый автоматический прогон: **23/23 теста успешно**.

## MEDIUM-1 — при обобщении изменилась эвристика 4×4 / 4

### Наблюдение

В исходной версии `0.3.0` Alpha–Beta использовал веса линий:

`[0, 2, 18, 180, 20 000]`.

При переходе к универсальному `ai-model.js` они неявно стали:

`[0, 2, 20, 200, 20 000]`.

Функционально алгоритм оставался сильным, но это было скрытым изменением уже разработанного варианта.

### Исправление

Для `winLength = 4` восстановлены исходные веса `0.3.0`.

Добавлен регрессионный тест, фиксирующий:

- веса эвристики;
- пороги глубины `5 / 6 / 7 / полный поиск`.

## MEDIUM-2 — объединённый интерфейс не запоминал выбранный режим

### Наблюдение

После обновления страницы приложение всегда возвращалось к `3×3`, даже если пользователь работает с одним из вариантов `4×4`.

В режиме с единым интерфейсом это создаёт повторяющееся действие, не добавляя полезной информации.

### Исправление

Добавлен ключ:

`ttt_selected_mode_v1`.

Последний выбранный режим восстанавливается автоматически. Новых настроек или кнопок для этого не добавлено, поэтому визуальная сложность не увеличилась.

При недоступном или повреждённом `localStorage` используется безопасный fallback на `3×3`.

## LOW-1 — описания режимов были длиннее необходимого

### Наблюдение

На узком мобильном экране длинные пояснения могли занимать три строки и смещать поле при переключении режима.

### Исправление

Описание сведено к одному продуктово важному свойству алгоритма:

- `3×3`: алгоритм без ошибок; лучший результат — ничья;
- `4×4 / 4`: сильный, но не гарантированно совершенный;
- `4×4 / 3`: X имеет выигрышную стратегию; защита оптимальна.

Размер и количество символов подряд уже находятся внутри переключателя и повторно в описании не дублируются.

## Архитектурная оценка

### Положительно

`modes.js` стал единственной точкой описания режимов.

`game-model.js` не знает о конкретных версиях игры и получает:

- размер поля;
- длину выигрышной последовательности.

`ai-model.js` сохраняет разные свойства разработанных алгоритмов:

- точный поиск — `3×3 / 3`;
- Alpha–Beta — `4×4 / 4`;
- точный поиск — `4×4 / 3`.

`script.js` отвечает за общий UI-flow и не содержит трёх отдельных веток отрисовки поля.

### Остаточное ограничение

UMD/browser globals (`TTTModes`, `TTTGame`, `TTTAI`, `TTTScore`) сохранены для запуска без сборщика. Для текущего размера это приемлемо.

## Счёт и совместимость

Объединение не создаёт новую общую статистику и не смешивает разные правила.

Используются прежние ключи:

- `ttt_score_v3`;
- `ttt_score_4x4_v1`;
- `ttt_score_4x4_k3_v1`.

Поэтому существующий счёт переносится в общий интерфейс без миграции.

В `3×3` скрывается недостижимый счётчик побед пользователя; модель всё равно умеет нормализовать старую двухсчётчиковую схему.

## UI/UX review

### Информационная иерархия

Экран имеет один основной поток:

1. название;
2. вариант игры;
3. краткое свойство режима;
4. счёт;
5. статус;
6. поле;
7. действия.

Дополнительный Setup-экран не требуется.

### Различимость режимов

Два варианта `4×4` различаются не только положением сегмента, но и второй строкой:

- `4 подряд`;
- `3 подряд`.

Это критично: один размер поля сам по себе не определяет правила.

### Минимализм

Не добавлены:

- модальные меню;
- иконки без функциональной необходимости;
- темы;
- уровни сложности;
- навигационная панель;
- отдельные карточки режимов.

Счёт визуально представлен текстовой строкой, а не тяжёлыми карточками.

## Accessibility

- Выбор режима реализован настоящими radio inputs внутри `fieldset`.
- Стрелочная клавиатурная навигация браузера сохранена.
- Поле остаётся набором `button`.
- Недоступность хода передаётся через `aria-disabled`, клетки остаются фокусируемыми.
- `aria-busy` сообщает время ответа алгоритма.
- Статус использует `aria-live`.
- X и O различаются не только цветом, но и символом.
- Последний ход и победная линия имеют отдельное контурное выделение.
- Сохранён `prefers-reduced-motion`.

## Реальный browser smoke-test

Интерфейс дополнительно запущен в Chromium через `page.set_content`, что обходит ограничение окружения на локальную HTTP-навигацию.

Проверено на viewport `390×844`:

- стартовый `3×3` строит 9 клеток;
- `ArrowRight` на radio-group переключает на `4×4`;
- после переключения строится 16 клеток;
- label-click корректно переключает оба варианта `4×4`;
- после хода X появляется `Алгоритм думает`;
- после задержки алгоритм делает ход;
- `aria-busy` возвращается в `false`;
- визуального переполнения на мобильной ширине не обнаружено.

## Финальная проверка

После исправлений:

- `node --check` — успешно;
- автоматические тесты — **27/27 успешно**;
- полный перебор всех человеческих линий `3×3` не даёт победы X против точного алгоритма;
- `4×4 / 3`: после каждого из 16 первых ходов X позиция O подтверждена как game-theoretic loss;
- `4×4 / 4`: сохранена исходная эвристика и тактическая блокировка;
- переключение режима отменяет ожидающий ход алгоритма;
- последний режим сохраняется и восстанавливается;
- browser smoke-test — успешно.

`ttt_0.5.0` объединяет три разработанных варианта в одном минималистичном интерфейсе без потери их ключевых игровых свойств.
