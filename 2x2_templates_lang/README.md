# 2x2 prototype — 2x2 Templates v1

Рабочий статический прототип по архитектурному заданию `2x2_architecture_1.0.0-draft.1.md` от 19.09.2026.

Исходная точка репозитория перед реализацией сверена: `t39s/2x2`, ветка `gh-pages`, commit `7da35e81e484051f0b9bb4936cc55190bf34023d`. Внешняя публикация и сам репозиторий не изменялись.

## Запуск

Приложению нужен HTTP(S); `file://` не является целевой средой.

```bash
cd 2x2-prototype
python3 -m http.server 8080
```

Открыть `http://localhost:8080/index.htm`.

## Реализовано

- `index.htm` сохранён как точка входа статического приложения;
- штатный набор `data/templates.json` с 8 историческими уровнями и 64 фиксированными выражениями в исходном порядке;
- отдельный `data/demo-templates.json` с генерируемыми упражнениями;
- импорт локального `.json` с ограничением 1 MiB;
- двухфазный импорт: валидация → просмотр уровней/до 10 примеров → явное «Использовать набор»;
- плохой файл не заменяет текущий рабочий набор;
- сохранение успешно активированного импорта в `localStorage` с деградацией до памяти при недоступном хранилище;
- структурный и семантический валидатор с отклонением неизвестных полей;
- отдельный JSON Schema Draft 2020-12;
- ограниченный парсер выражений с AST, без `eval` и `Function`;
- целые числа, `+ - * / %`, унарный знак, скобки, точное деление, диапазон ±1 000 000;
- `variables`, `derived`, `constraints`, `expression`, `prompt + answer`;
- топологическая сортировка `derived`, неизвестные имена и циклы отклоняются до старта;
- конечный перебор комбинаций, математическая фильтрация, дедупликация условий и выбор без возвращения;
- построение пула порциями с уступкой event loop каждые 1000 комбинаций и возможностью отмены;
- сохранение конкретной последовательности заданий до первого показа;
- мобильная экранная клавиатура `1…9`, `±`, `0`, `⌫`, отдельная кнопка «Ответить»;
- аппаратные цифры, `-`, Backspace и Enter через тот же обработчик действий;
- ввод без системного текстового поля, поэтому экранная системная клавиатура смартфона не требуется;
- явный контроллер сеанса без перезагрузки страницы после каждого ответа;
- время считается только от показа задания до отправки ответа; feedback-пауза не учитывается;
- reload/уход вкладки в фон делает сеанс прерванным; сохраняются набор, уровень, конкретные задания и введённый ответ;
- прерванный сеанс можно продолжить, но он не открывает следующий уровень;
- последовательное открытие уровней, отчёт и отдельное хранение прогресса для `id/revision` набора;
- вывод импортированного текста только через `textContent`.

## Проверки

```bash
node tests/core.test.js
```

На текущей сборке: **17 passed, 0 failed**.

Отдельно оба комплектных JSON-файла проверены Python `jsonschema` по `schema/2x2-templates.schema.json` — PASS.

Проверки включают:

- все 64 исторических выражения: порядок, скобочная структура и ожидаемые ответы;
- `2 + 3 * 4 = 14`;
- `(2 + 3) * 4 = 20`;
- `7 - (9 + 7) = -9`;
- `8 / 2 * 2 = 8`;
- `-7 % 3 = -1`;
- ровно 36 упорядоченных пар для сложения через десяток;
- целочисленный пул табличного деления;
- цикл `derived`;
- повтор значения в `values`;
- неизвестное поле;
- JavaScript-подобную инъекцию;
- пустой пул;
- нехватку вариантов при `count` больше размера пула.

## Структура

- `index.htm` — интерфейс;
- `styles.css` — адаптивная компоновка;
- `core.js` — язык, валидатор, интерпретатор и генератор;
- `app.js` — загрузка наборов, импорт, сеанс, прогресс и UI;
- `data/templates.json` — исходные 8 уровней;
- `data/demo-templates.json` — демонстрационный генерируемый набор;
- `schema/2x2-templates.schema.json` — JSON Schema;
- `tests/core.test.js` — автоматические проверки ядра;
- `docs/2x2_architecture_1.0.0-draft.1.md` — исходное архитектурное задание;
- `TEST_RESULTS.md` — фактические результаты проверки этой сборки.

## Что ещё не подтверждено

Это прототип, а не принятый release.

- Реальный Safari/iPhone не проверялся; адаптивная вёрстка под 320/375/390/430 CSS px требует внешней приёмки на устройстве.
- Максимальный разрешённый пул не измерялся на целевом iPhone.
- Пулы выполняются порциями в основном потоке, а не в Web Worker.
- Runtime использует собственную структурную проверку; JSON Schema поставляется и отдельно валидируется, но в браузере внешняя библиотека JSON Schema не подключена.
- Runtime-валидатор сейчас возвращает первую найденную структурную/семантическую ошибку, а не агрегирует весь список за один проход.
- Смысловая связь свободного `prompt` и формулы `answer` автоматически не доказывается.
- Визуального редактора шаблонов нет.
