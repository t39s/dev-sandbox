# 2x2: язык шаблонов и задание на доработку

Версия: 1.0.0-draft.1. Дата исследования: 19.09.2026.
Адресат: разработчик GPT 5.6 Sol. Статус: архитектурное предложение владельцу; приложение в рамках этой работы не изменялось.

## 1. Решение

Предлагается небольшой декларативный язык **2x2 Templates v1**: внешний JSON, внутри которого учитель задаёт переменные, допустимые значения, математическое выражение и при необходимости ограничения. Приложение создаёт конкретные задания, вычисляет ответы и проводит тренировку.

Для основного сценария условие и ответ выводятся из одной формулы. Учитель не должен независимо писать `a + b` в условии и `a - b` в ответе: такое расхождение нужно исключить конструкцией формата. Отдельный режим текстовой задачи допускает собственные текст и формулу ответа; его смысловую правильность проверяет учитель.

JSON — формат хранения и обмена. Математические выражения — небольшой предметный язык. Русские названия и пояснения — интерфейс учителя. Это разные уровни, смешивать их не следует.

Первая версия: целые числа, включая отрицательные; сложение, вычитание, умножение, точное деление, скобки, один числовой ответ. Дроби, проценты с округлением, несколько полей ответа, символьное решение уравнений и автоматическая интерпретация свободного русского текста отложены.

## 4. Как учитель описывает задание

Пример замысла: «Сложение двух однозначных положительных чисел с переходом через десяток».

```json
{
  "id": "addition-over-ten",
  "title": "Сложение с переходом через десяток",
  "variables": {
    "a": { "min": 1, "max": 9 },
    "b": { "min": 1, "max": 9 }
  },
  "expression": "a + b",
  "constraints": ["a + b > 10"]
}
```

Учитель меняет диапазоны и формулу. Приложение может получить `7 + 6 = ?` с ответом 13 или `8 + 5 = ?` с ответом 13. `3 + 4` не подходит. Сумма 10 сознательно исключена: условие написано как `> 10`, а не `>= 10`.

Для проверки языка полезна такая памятка:

| Поле | Смысл для учителя |
|---|---|
| `title` | Название упражнения |
| `variables` | Какие числа выбирать |
| `derived` | Какие числа вычислить из выбранных |
| `expression` | Что предложить ученику вычислить |
| `constraints` | Какие сочетания допускаются |
| `prompt` + `answer` | Текстовая задача и формула ответа вместо `expression` |

В v1 учитель может редактировать JSON по примерам и загружать файл. Обязателен экран проверки с понятными ошибками и предпросмотром. Полноценный визуальный редактор шаблонов — следующий этап, а не скрытая часть этой доработки. В дальнейшем его русские поля должны создавать тот же JSON, без второго языка хранения.

## 5. Полный минимальный файл

```json
{
  "format": "2x2-templates",
  "version": 1,
  "id": "mental-arithmetic",
  "revision": 1,
  "title": "Устный счёт",
  "templates": [
    {
      "id": "addition-over-ten",
      "title": "Сложение с переходом через десяток",
      "variables": {
        "a": { "min": 1, "max": 9 },
        "b": { "min": 1, "max": 9 }
      },
      "expression": "a + b",
      "constraints": ["a + b > 10"]
    }
  ],
  "levels": [
    {
      "id": "level-1",
      "title": "Уровень 1",
      "maxErrors": 1,
      "maxSeconds": 30,
      "items": [
        { "templateId": "addition-over-ten", "count": 8 }
      ],
      "shuffle": true
    }
  ]
}
```

`version` — версия языка, `revision` — редакция конкретного учебного набора. При изменении заданий учитель увеличивает `revision`. Прогресс разных наборов не смешивать. Внутри сеанса хранить фактически использованный набор и конкретные задания: одна пара `id/revision` не защищает от ошибочного редактирования файла без увеличения номера.

## 6. Нормативный контракт предлагаемого v1

### Структура

Обязательные поля корня: все показанные в полном примере. `templates` и `levels` — непустые массивы. Идентификаторы уникальны в своей области, имеют формат `[a-z][a-z0-9-]{0,63}`. `revision` — положительное целое, `version` — ровно 1. Неизвестные поля отклонять во всех объектах, чтобы опечатки не меняли смысл молча.

Шаблон: обязательны `id`, `title` и ровно один из режимов:

1. `expression`: одна арифметическая формула; она же источник отображения и ответа.
2. `prompt` и `answer`: текст с подстановками и арифметическая формула ответа.

`variables`, `derived`, `constraints` необязательны; значения по умолчанию `{}`, `{}`, `[]`. Выражение без переменных — фиксированное задание. `title` и `prompt` — обычный текст, не HTML.

Уровень: обязательны `id`, `title`, `maxErrors`, `maxSeconds`, `items`, `shuffle`. `maxErrors` — целое от 0 до числа заданий; `maxSeconds` — положительное целое. `items` содержит уникальные `templateId` и положительное `count`. Порядок уровней — порядок прохождения. Первый открыт сразу, остальные открываются последовательно. Повтор уже открытого уровня не закрывает последующие.

### Переменные и зависимости

Имя переменной: `[a-z][a-z0-9_]{0,31}`. Регистр значим. Запретить служебные имена `__proto__`, `prototype`, `constructor`. Окружение вычислений — Map или объект без прототипа.

Ровно одна форма области значений:

- `{ "min": -9, "max": 9 }`: все целые между границами включительно;
- `{ "values": [2, 3, 5, 7] }`: непустое множество целых без повторов.

Границы — числа, не выражения. Зависимые значения записываются в `derived`, например `{ "n": "d * q" }`. Имена `variables` и `derived` не пересекаются. Порядок ключей JSON ничего не определяет: зависимости вычисляются топологически. Неизвестное имя, ссылка на себя или цикл — ошибка всего файла. Случайность разрешена только при выборе конкретного задания; вызовов `random()` внутри формул нет.

### Грамматика выражений

```ebnf
expression = term, { ("+" | "-"), term } ;
term       = unary, { ("*" | "/" | "%"), unary } ;
unary      = ["+" | "-"], primary ;
primary    = integer | name | "(", expression, ")" ;
constraint = expression, relation, expression ;
relation   = "==" | "!=" | "<" | "<=" | ">" | ">=" ;
```

`integer` — `0` или последовательность цифр без начального нуля; знак задаётся унарным оператором. Пробелы допускаются между токенами. Нет неявного умножения, функций, присваивания, свойств объектов, строк, экспоненциальной записи или цепочек сравнений. Все элементы массива `constraints` соединяются логическим И. Например, `0 <= a <= 9` следует записать двумя условиями.

В формулах используются ASCII `* / -`; отображение заменяет их на `× ÷ −`. Все бинарные операции одного приоритета выполняются слева направо. Скобки сохраняются, в том числе учебно значимые избыточные: `a + (b + c)` нельзя сокращать до `a + b + c`.

Все исходные числа, промежуточные результаты и ответы — целые в диапазоне −1 000 000…1 000 000. `/` допустим только при ненулевом делителе и точном целом частном. `%` — остаток с знаком делимого, как в JavaScript для целых; учителю предлагать его прежде всего для проверки делимости. Ноль нормализуется, отрицательного нуля нет. Выход за диапазон, деление на ноль или нецелое частное исключают конкретное сочетание значений; синтаксическая ошибка исключает весь файл.

Интерпретатор строит AST; `eval`, `Function` и исполнение строк как JavaScript запрещены. Скобочные узлы сохраняются для отображения. Отрицательное подставляемое число в позиции операнда заключать в скобки: `a - b` при `b=-3` показывает `5 − (−3)`, а не `5 − −3`.

### Текстовые задания

`prompt` поддерживает только подстановки `{name}` известных переменных. Выражения внутри фигурных скобок запрещены: вычислить значение через `derived`. Литералы фигурных скобок в v1 не поддерживаются; несогласованные скобки — ошибка. Экранировать текст при выводе через DOM; не присваивать его `innerHTML`.

Движок проверяет численную корректность `answer`, но не доказывает соответствие произвольного текста формуле. На экране учителя показывать условия, значения переменных и ответы. Задания с пропуском через текст ниже имеют явно заданный ответ; универсального решателя уравнений здесь нет.

## 7. Примеры возможностей

Каждый блок — отдельный элемент массива `templates`.

### Вычитание без отрицательного ответа

```json
{
  "id": "subtraction",
  "title": "Вычитание до 20",
  "variables": { "a": { "min": 0, "max": 20 }, "b": { "min": 0, "max": 20 } },
  "expression": "a - b",
  "constraints": ["a >= b"]
}
```

### Скобки и отрицательные числа

```json
{
  "id": "parentheses",
  "title": "Вычитание суммы",
  "variables": {
    "a": { "min": -9, "max": 9 },
    "b": { "min": 1, "max": 9 },
    "c": { "min": 1, "max": 9 }
  },
  "expression": "a - (b + c)"
}
```

### Деление без остатка: сначала выбрать делитель и частное

```json
{
  "id": "division",
  "title": "Табличное деление",
  "variables": { "d": { "min": 2, "max": 9 }, "q": { "min": 2, "max": 9 } },
  "derived": { "n": "d * q" },
  "expression": "n / d"
}
```

Пример: `56 ÷ 7`, ответ 8. Вычисляемая переменная `n` отображается числом 56, а не разворачивается в `7 × 8`: иначе условие раскроет способ построения.

### Неизвестное слагаемое

```json
{
  "id": "missing-addend",
  "title": "Найди пропущенное число",
  "variables": { "a": { "min": 1, "max": 9 }, "x": { "min": 1, "max": 9 } },
  "derived": { "s": "a + x" },
  "prompt": "{a} + □ = {s}",
  "answer": "x"
}
```

### Короткая текстовая задача

```json
{
  "id": "boxes",
  "title": "Карандаши в коробках",
  "variables": { "n": { "values": [2, 3, 4] }, "k": { "min": 2, "max": 9 } },
  "prompt": "Коробок: {n}. В каждой по {k} карандашей. Сколько карандашей всего?",
  "answer": "n * k"
}
```

Формулировка не требует автоматического склонения существительных. Склонение не входит в v1.

## 8. Генерация: конечный пул вместо бесконечных попыток

Для маленьких диапазонов устного счёта предлагается полный перебор допустимых комбинаций при подготовке уровня. Это позволяет точно обнаружить невозможное условие и нехватку различных заданий.

1. Проверить JSON, схему, ссылки, грамматику и зависимости.
2. Для нужных шаблонов перечислить декартово произведение областей `variables` в фиксированном порядке имён и значений. Без переменных имеется одно сочетание.
3. Вычислить `derived`, ограничения и ответ; исключить математически недопустимые сочетания.
4. Сформировать условие, убрать дубликаты по каноническому условию внутри шаблона. Если одинаковое условие даёт разные ответы — отклонить шаблон как неоднозначный.
5. Выбрать `count` различных условий равновероятно без возвращения из пула каждого шаблона, затем при `shuffle=true` перемешать итоговую последовательность.
6. Сохранить конкретную последовательность до показа первого задания. Проверять ответы по этим объектам; никогда не генерировать повторно во время проверки или отчёта.

Для выражений ключ условия строится по отображаемой математической структуре после подстановки; пробельные различия не учитываются, скобки и порядок операндов учитываются. `3 + 7` и `7 + 3` — разные задания. Равномерность относится к различным условиям внутри шаблона, не к ответам: равномерные ответы не обещаются.

Гарантия отсутствия повторов действует внутри одного шаблона одного сеанса. Разные шаблоны могут дать одинаковые условия; показать предупреждение учителю, не обещать глобальную уникальность. Количество каждого типа определяется `count`, а не случайными весами. Между сеансами повторения допустимы.

Ограничения v1: файл до 1 MiB UTF-8; до 100 шаблонов и 100 уровней; до 8 случайных и 8 вычисляемых переменных на шаблон; не более 100 000 исходных сочетаний на шаблон и 500 000 суммарно на выбранный уровень; до 100 заданий в уровне; до 16 ограничений; формула до 256 символов и глубины 16; текст условия до 500 символов, название до 120. Ограничения — предлагаемые продуктовые границы, не результат замера производительности.

Перебор выполнять в Worker или порциями с возможностью отмены. Не расширять лимиты без замеров на смартфоне. При превышении лимита объяснять, какие диапазоны уменьшить. Пустой пул и `count` больше размера пула запрещают старт; нельзя ослаблять ограничения, добавлять повторы или уменьшать число заданий молча. При размере пула 1 запрос двух заданий завершается понятной ошибкой.

## 9. Внешний JSON и работа учителя

Обязательны два пути одного и того же загрузчика:

- штатный файл `data/templates.json`, получаемый по относительному URL;
- кнопка «Загрузить задания» и выбор `.json` из файлов устройства, в том числе на iPhone/iPad.

Произвольный URL не обязателен в v1: он добавляет CORS и сетевые ошибки без необходимости для базового сценария. Не подменять JSON подключением `<script>`. Штатная версия работает на статическом HTTPS-хостинге; открытие страницы как `file://` не входит в целевую среду.

После импорта: показать название, редакцию, уровни и ошибки, дать выбрать уровень и посмотреть до 10 примеров с ответами. Пользовательская кнопка «Использовать набор» активирует только прошедший проверку набор. Ошибка файла не заменяет предыдущий рабочий набор. Ошибки генерации уровня блокируют этот уровень и показываются до начала тренировки. Во время сеанса импорт недоступен.

Сообщения: `Шаблон subtraction, constraints[0]: неизвестная переменная c`; `Найдено 5 различных заданий, запрошено 8`; `Условию не соответствует ни одно сочетание чисел`. Сетевую ошибку отличать от синтаксической. Предусмотреть возврат к штатному набору.

Сохранённый импорт можно использовать после перезагрузки страницы; это не обещание офлайн-запуска приложения. Обработать недоступное хранилище: продолжить в памяти с явным сообщением об отсутствии сохранения.

## 10. Интерфейс ученика

Портретный экран: название уровня и прогресс; крупное условие; поле ответа; цифровая клавиатура; обратная связь. Клавиатура: строки `1 2 3`, `4 5 6`, `7 8 9`, `± 0 ⌫`; отдельно широкая кнопка «Ответить». Размер каждой кнопки не менее 56 × 56 CSS px, расстояние между кнопками не менее 8 px. Это проектное требование, а не ссылка на стандарт доступности.

Кнопка `±` нужна всегда: отрицательные ответы уже есть в исходных заданиях. Пустой ответ и одиночный минус не отправляются; ноль — полноценный ответ. `⌫` удаляет один символ. После проверки ввод блокируется, результат фиксируется ровно один раз. Через секунду показывается следующее задание; на последнем — отчёт.

Поддержать аппаратные цифры, минус, Backspace и Enter тем же обработчиком действий. Системная клавиатура на смартфоне не должна перекрывать экранные кнопки. Доступные подписи, видимый фокус, обратная связь текстом, а не только цветом. Не запрещать масштабирование страницы.

Проверить ширины 320, 375, 390 и 430 CSS px; на высоте видимой области 568 px короткое арифметическое условие, ответ и клавиатура помещаются без прокрутки. Для длинного текста и увеличенного шрифта допускается вертикальная прокрутка, горизонтальная — нет. Учесть безопасные отступы и изменение доступной высоты при появлении панелей браузера.

## 11. Сеанс, время и прогресс

Состояния: выбор набора/уровня → подготовка → ответ → обратная связь → следующий ответ либо отчёт. Ошибка подготовки возвращает к выбору с объяснением. Двойной тап не создаёт два результата.

Время уровня — сумма интервалов от показа задания до отправки ответа. Загрузка, подготовка пула и секундная обратная связь не учитываются. Успех: `errors <= maxErrors` и `elapsedSeconds <= maxSeconds`; превышение времени не обрывает ввод, как и в текущем сценарии все задания доводятся до отчёта.

В предложенном v1 перезагрузка во время ответа сохраняет конкретное задание и введённый ответ, но отмечает сеанс как прерванный: результаты доступны, следующий уровень им не открывается. Ученику предлагают продолжить тренировку без зачёта времени либо начать заново. Переход вкладки в фон также делает сеанс прерванным. Это явное изменение относительно старой реализации, выбранное ради честной временной оценки; разработчик должен описать его владельцу в комплекте приёмки.

Прогресс хранить отдельно от сеанса, в ключах с префиксом приложения и версией схемы. Старые cookie не интерпретировать как прогресс нового набора; не удалять все cookie домена. Исходные наборы сохранить в режиме фиксированных формул с порядком заданий и прежними порогами. Сгенерированный набор оформить отдельно: не подменять исходные упражнения по одним лишь названиям уровней.

## 12. Задание GPT 5.6 Sol

Разработать доработку существующего статического приложения, сохранив доступность исходного `index.htm`. Не внедрять сервер, учётные записи или внешний LLM. Предлагаемое логическое разделение, без требования точных имён файлов:

| Компонент | Ответственность |
|---|---|
| Загрузчик и валидатор | JSON, схема, версии, ссылки, диагностика |
| Парсер и интерпретатор | AST, типы, зависимости, арифметика |
| Генератор | Пулы, фильтрация, дедупликация, выбор |
| Контроллер сеанса | Последовательность, ответы, время, переходы |
| Хранилище | Снимок сеанса, набор, прогресс |
| Представление | DOM, клавиатура, адаптивная вёрстка, отчёт |

Последовательность реализации:

1. Зафиксировать исследуемый commit и регрессионные данные 64 примеров; уточнить изменения HEAD.
2. Реализовать JSON Schema и семантический валидатор по этому контракту; написать парсер и генератор независимо от DOM.
3. Перевести старые задания в фиксированные JSON-шаблоны и добавить демонстрационные генерируемые упражнения.
4. Внедрить контроллер сеанса, затем мобильный интерфейс и загрузку файлов.
5. Выполнить внутренние проверки и подготовить комплект внешней приёмки на телефоне.

Внутренняя проверка разработчика не равна приёмке владельца на iPhone. Не заявлять проверку реального Safari, если была только эмуляция.

### Обязательные проверки

| Сценарий | Проверяемый результат |
|---|---|
| Все 64 старых выражения | Независимо проверенные ответы совпадают; порядок и скобки сохранены |
| `2 + 3 * 4`, `(2 + 3) * 4`, `7 - (9 + 7)` | 14, 20, −9 |
| `8 / 2 * 2`, `-7 % 3` | 8, −1 |
| Деление по шаблону `division` | Весь пул целочисленный, делитель ненулевой |
| Сложение через десяток | Пул ровно 36 упорядоченных пар, каждая сумма > 10 |
| Диапазоны и наборы значений | Обе границы включены; повтор значения в `values` отклонён |
| Цикл `a=b+1`, `b=a+1` в derived | Ошибка до старта |
| `a > 10` при `a` от 1 до 9 | Пустой пул, без зависания |
| Один вариант, count=2 | Ошибка нехватки вариантов |
| `window.alert(1)`, неизвестное имя, неизвестное поле | Отклонение без исполнения |
| HTML в title/prompt | Показан как текст, код не выполняется |
| Ноль, минус, исправление и повторный Enter | Строгий целочисленный ввод; одна отправка |
| Плохой файл после хорошего | Хороший набор сохранён |
| Reload/фон во время задания | Тот же конкретный пример; сеанс помечен прерванным |
| Ошибки/время точно на границе порога | Уровень пройден; превышение любого порога — не пройден |
| Максимальный разрешённый пул | Интерфейс отвечает, подготовку можно отменить |
| Портретный Safari iPhone, выбор JSON из файлов | Импорт, ввод отрицательного ответа и отчёт доступны через интерфейс |

Для проверки генератора пройти все комбинации небольших учебных шаблонов; проверять числа отдельным эталонным расчётом, а не тем же интерпретатором. Для случайного выбора предусмотреть подменяемый источник случайности в тестах; сохранение реальных заданий обязательно независимо от seed.

### Передаваемый результат реализации

Runtime-файлы приложения, JSON Schema, исходный и демонстрационный наборы, руководство учителю с примерами, инструкция установки на статический хостинг, внутренние тесты с фактическими результатами, сценарий приёмки на смартфоне и перечень известных ограничений. Не изменять внешнюю публикацию в рамках подготовки к приёмке без соответствующего поручения.
