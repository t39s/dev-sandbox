# 2x2 Templates v1 — инструкция по созданию заданий

Версия инструкции: 1.0  
Для приложения: 2x2 0.1.0-rc.4  
Формат: `2x2-templates`, `version: 1`

## 1. Что такое язык шаблонов

2x2 Templates v1 — это JSON-формат, в котором задаются:

- набор учебных шаблонов (`templates`);
- переменные и их допустимые значения;
- формула задания;
- дополнительные ограничения на допустимые сочетания чисел;
- при необходимости вычисляемые переменные (`derived`);
- уровни (`levels`) и количество заданий каждого типа.

Приложение само:

1. проверяет файл;
2. перебирает допустимые значения переменных;
3. отбрасывает комбинации, не удовлетворяющие ограничениям;
4. вычисляет правильный ответ;
5. выбирает нужное количество различных заданий;
6. проводит тренировку.

В формулах не используется JavaScript. `eval`, функции, обращения к объектам и произвольный код не поддерживаются.

---

## 2. Минимальная структура файла

```json
{
  "format": "2x2-templates",
  "version": 1,
  "id": "my-arithmetic-set",
  "revision": 1,
  "title": "Мои задания",
  "templates": [
    {
      "id": "addition",
      "title": "Сложение",
      "variables": {
        "a": { "min": 1, "max": 9 },
        "b": { "min": 1, "max": 9 }
      },
      "expression": "a + b"
    }
  ],
  "levels": [
    {
      "id": "level-1",
      "title": "Уровень 1",
      "maxErrors": 1,
      "maxSeconds": 30,
      "items": [
        { "templateId": "addition", "count": 8 }
      ],
      "shuffle": true
    }
  ]
}
```

### Обязательные поля корня

| Поле | Значение |
|---|---|
| `format` | всегда `"2x2-templates"` |
| `version` | всегда `1` |
| `id` | идентификатор учебного набора |
| `revision` | номер редакции набора, целое число от 1 |
| `title` | название набора |
| `templates` | массив шаблонов |
| `levels` | массив уровней |

Если вы изменили содержание учебного набора, увеличьте `revision`.

## 3. Правила идентификаторов

### `id` набора, шаблона и уровня

Формат:

```text
[a-z][a-z0-9-]{0,63}
```

Подходят:

```text
addition
addition-over-ten
level-1
mental-arithmetic-2
```

Не подходят:

```text
Addition
level_1
1-level
уровень-1
```

### Имена переменных

Формат:

```text
[a-z][a-z0-9_]{0,31}
```

Подходят:

```text
a
b
number1
left_value
```

Регистр значим. Имена `a` и `A` не равнозначны; при этом `A` вообще не соответствует допустимому формату.

Не используйте служебные имена:

```text
__proto__
prototype
constructor
```

## 4. Два типа шаблонов

У шаблона должны быть `id`, `title` и ровно один из двух режимов.

### Режим A: математическое выражение

Используйте `expression`.

```json
{
  "id": "addition",
  "title": "Сложение",
  "variables": {
    "a": { "min": 1, "max": 9 },
    "b": { "min": 1, "max": 9 }
  },
  "expression": "a + b"
}
```

Одно и то же выражение служит:

- условием задания;
- источником правильного ответа.

Это основной режим для устного счёта.

### Режим B: текстовое условие + формула ответа

Используйте одновременно `prompt` и `answer`.

```json
{
  "id": "boxes",
  "title": "Карандаши в коробках",
  "variables": {
    "n": { "values": [2, 3, 4] },
    "k": { "min": 2, "max": 9 }
  },
  "prompt": "Коробок: {n}. В каждой по {k} карандашей. Сколько карандашей всего?",
  "answer": "n * k"
}
```

Здесь приложение проверяет численную формулу ответа, но не понимает смысл русского текста. Соответствие текста формуле проверяет автор задания.

Нельзя одновременно указывать `expression` и `prompt`/`answer`.

## 5. Переменные: `variables`

У каждой переменной допустима ровно одна форма области значений.

### Диапазон целых чисел

```json
"a": { "min": 1, "max": 9 }
```

Обе границы включены.

Например:

```json
"a": { "min": -9, "max": 9 }
```

даёт все целые от −9 до 9.

### Явный список значений

```json
"n": { "values": [2, 3, 5, 7] }
```

Повторы запрещены:

```json
"n": { "values": [2, 2, 3] }
```

будет ошибкой.

### Важно

Границы `min` и `max` — только числа. Нельзя писать:

```json
"a": { "min": "b + 1", "max": 9 }
```

Зависимые значения задаются через `derived`.

---

## 6. Вычисляемые переменные: `derived`

`derived` применяется, когда одно число нужно вычислить из других.

Пример: сначала выбрать делитель и частное, затем получить делимое.

```json
{
  "id": "division",
  "title": "Табличное деление",
  "variables": {
    "d": { "min": 2, "max": 9 },
    "q": { "min": 2, "max": 9 }
  },
  "derived": {
    "n": "d * q"
  },
  "expression": "n / d"
}
```

При `d = 7`, `q = 8` приложение покажет:

```text
56 ÷ 7
```

а не:

```text
7 × 8 ÷ 7
```

`derived` может зависеть от других `derived`. Порядок ключей в JSON значения не имеет: зависимости вычисляются автоматически.

Циклы запрещены. Например:

```json
"derived": {
  "a": "b + 1",
  "b": "a + 1"
}
```

являются ошибкой.

Имена `variables` и `derived` не должны совпадать.

## 7. Арифметический язык выражений

Поддерживаются:

```text
+   сложение
-   вычитание
*   умножение
/   точное целочисленное деление
%   остаток от деления
( ) скобки
```

Также поддерживается унарный плюс и минус:

```text
-a
+5
-(a + b)
```

### Приоритет операций

Стандартный:

1. скобки;
2. унарный `+` и `-`;
3. `*`, `/`, `%`;
4. `+`, `-`.

Операции одного приоритета выполняются слева направо.

Примеры:

```text
2 + 3 * 4      -> 14
(2 + 3) * 4    -> 20
8 / 2 * 2      -> 8
```

### Деление

`/` разрешено только тогда, когда:

- делитель не равен нулю;
- результат — точное целое число.

Например:

```text
8 / 2    допустимо
7 / 2    недопустимо для конкретной комбинации
5 / 0    недопустимо
```

Недопустимая математически комбинация просто исключается из пула заданий.

### Остаток `%`

Используется как целочисленный остаток со знаком делимого.

```text
-7 % 3 -> -1
```

Обычно `%` удобно применять в ограничениях для проверки делимости.

### Что запрещено

Нельзя писать:

```text
Math.random()
random()
pow(a, 2)
a ** 2
a.b
window.alert(1)
a = 5
"text"
2a
```

Нет функций, строк, свойств объектов, присваивания, неявного умножения и исполнения JavaScript.

## 8. Ограничения: `constraints`

`constraints` определяют, какие сочетания переменных допустимы.

Пример: сложение двух однозначных положительных чисел с переходом через десяток.

```json
{
  "id": "addition-over-ten",
  "title": "Сложение с переходом через десяток",
  "variables": {
    "a": { "min": 1, "max": 9 },
    "b": { "min": 1, "max": 9 }
  },
  "expression": "a + b",
  "constraints": [
    "a + b > 10"
  ]
}
```

Поддерживаются отношения:

```text
==
!=
<
<=
>
>=
```

Все элементы `constraints` соединяются логическим И.

Например:

```json
"constraints": [
  "a >= 0",
  "a <= 9",
  "a != 5"
]
```

Цепочки сравнений не поддерживаются. Нельзя:

```text
0 <= a <= 9
```

Нужно:

```json
"constraints": [
  "0 <= a",
  "a <= 9"
]
```

### Пример: вычитание без отрицательного ответа

```json
{
  "id": "subtraction",
  "title": "Вычитание до 20",
  "variables": {
    "a": { "min": 0, "max": 20 },
    "b": { "min": 0, "max": 20 }
  },
  "expression": "a - b",
  "constraints": ["a >= b"]
}
```

## 9. Текстовые задания: `prompt`

В `prompt` можно подставлять только известные имена переменных и `derived`:

```json
{
  "id": "missing-addend",
  "title": "Найди пропущенное число",
  "variables": {
    "a": { "min": 1, "max": 9 },
    "x": { "min": 1, "max": 9 }
  },
  "derived": {
    "s": "a + x"
  },
  "prompt": "{a} + □ = {s}",
  "answer": "x"
}
```

Нельзя помещать выражение внутрь `{...}`:

```text
{a + b}
```

Вместо этого создайте `derived`:

```json
"derived": {
  "sum": "a + b"
},
"prompt": "Сумма равна {sum}"
```

В v1 нет специального способа вывести литеральные фигурные скобки в тексте.

HTML в `title` и `prompt` не исполняется и выводится как обычный текст.

## 10. Фиксированные задания без генерации

Если переменные не нужны, просто задайте выражение.

```json
{
  "id": "fixed-1",
  "title": "Фиксированное задание 1",
  "expression": "7 - (9 + 7)"
}
```

Так можно перенести заранее подготовленный список упражнений.

Чтобы сохранить точный порядок восьми фиксированных заданий:

```json
"items": [
  { "templateId": "fixed-1", "count": 1 },
  { "templateId": "fixed-2", "count": 1 },
  { "templateId": "fixed-3", "count": 1 }
],
"shuffle": false
```

## 11. Уровни: `levels`

Пример:

```json
{
  "id": "level-1",
  "title": "Уровень 1",
  "maxErrors": 1,
  "maxSeconds": 30,
  "items": [
    { "templateId": "addition-over-ten", "count": 8 }
  ],
  "shuffle": true
}
```

### Поля уровня

- `id` — уникальный идентификатор уровня;
- `title` — название;
- `maxErrors` — максимально допустимое число ошибок;
- `maxSeconds` — максимально допустимое суммарное время ответов в секундах;
- `items` — какие шаблоны входят в уровень;
- `shuffle` — перемешивать итоговую последовательность или нет.

### `items`

```json
{ "templateId": "division", "count": 4 }
```

означает: выбрать 4 различных задания из пула шаблона `division`.

Один `templateId` нельзя повторять внутри одного уровня.

Суммарно в уровне должно быть не более 100 заданий.

### Смешанный уровень

```json
"items": [
  { "templateId": "division", "count": 4 },
  { "templateId": "missing-addend", "count": 4 }
],
"shuffle": true
```

Будет подготовлено 8 заданий: 4 одного типа и 4 другого.

## 12. Как работает генерация

Для каждого используемого шаблона приложение создаёт конечный пул.

Например:

```json
"variables": {
  "a": { "min": 1, "max": 9 },
  "b": { "min": 1, "max": 9 }
}
```

даёт 81 исходную комбинацию `(a, b)`.

Далее приложение:

1. вычисляет `derived`;
2. проверяет `constraints`;
3. вычисляет условие и ответ;
4. исключает математически недопустимые комбинации;
5. удаляет дубликаты одинаковых условий внутри шаблона;
6. случайно выбирает `count` различных условий без возвращения.

Если допустимых заданий меньше, чем запрошено, уровень не стартует.

Например, если пул содержит 5 различных условий, а указано:

```json
{ "templateId": "my-template", "count": 8 }
```

приложение сообщит о нехватке вариантов.

Приложение не ослабляет ограничения и не добавляет повторы автоматически.

## 13. Отрицательные числа и отображение

Отрицательные значения поддерживаются.

Например:

```json
"variables": {
  "a": { "min": -9, "max": 9 }
}
```

Если отрицательное число подставляется в позицию операнда, приложение отображает его со скобками там, где это необходимо для однозначности.

Например шаблон:

```text
a - b
```

при `a = 5`, `b = -3` отображается как:

```text
5 − (−3)
```

В JSON-формуле используйте ASCII-символы:

```text
* / -
```

На экране приложение само показывает математические знаки `×`, `÷`, `−`.

## 14. Практические примеры

### 14.1 Сумма ровно от 11 до 15

```json
{
  "id": "sum-11-15",
  "title": "Сумма от 11 до 15",
  "variables": {
    "a": { "min": 2, "max": 9 },
    "b": { "min": 2, "max": 9 }
  },
  "expression": "a + b",
  "constraints": [
    "a + b >= 11",
    "a + b <= 15"
  ]
}
```

### 14.2 Умножение на числа 2, 5 и 10

```json
{
  "id": "multiply-selected",
  "title": "Умножение на 2, 5 и 10",
  "variables": {
    "a": { "min": 1, "max": 9 },
    "b": { "values": [2, 5, 10] }
  },
  "expression": "a * b"
}
```

### 14.3 Деление с гарантированным целым ответом

Предпочтительный способ — строить делимое через `derived`:

```json
{
  "id": "exact-division",
  "title": "Деление без остатка",
  "variables": {
    "d": { "min": 2, "max": 9 },
    "q": { "min": 2, "max": 9 }
  },
  "derived": {
    "n": "d * q"
  },
  "expression": "n / d"
}
```

### 14.4 Деление через ограничение делимости

Также возможно:

```json
{
  "id": "exact-division-filtered",
  "title": "Деление без остатка",
  "variables": {
    "n": { "min": 10, "max": 99 },
    "d": { "min": 2, "max": 9 }
  },
  "expression": "n / d",
  "constraints": [
    "n % d == 0"
  ]
}
```

Для учебных таблиц первый вариант обычно проще и эффективнее.

### 14.5 Неизвестное уменьшаемое

```json
{
  "id": "missing-minuend",
  "title": "Найди уменьшаемое",
  "variables": {
    "b": { "min": 1, "max": 9 },
    "x": { "min": 1, "max": 9 }
  },
  "derived": {
    "a": "b + x"
  },
  "prompt": "□ − {b} = {x}",
  "answer": "a"
}
```

## 15. Ограничения v1

Текущая версия рассчитана на короткие упражнения по устному счёту.

Основные продуктовые пределы:

- файл до 1 MiB UTF-8;
- до 100 шаблонов;
- до 100 уровней;
- до 8 случайных переменных на шаблон;
- до 8 `derived` на шаблон;
- до 16 ограничений;
- формула до 256 символов;
- глубина выражения до 16;
- текст `prompt` до 500 символов;
- название до 120 символов;
- до 100 000 исходных комбинаций на один шаблон;
- до 500 000 исходных комбинаций суммарно на выбранный уровень;
- до 100 заданий в уровне;
- все числа, промежуточные результаты и ответы: от −1 000 000 до 1 000 000.

Не поддерживаются:

- дробные ответы;
- округление процентов;
- несколько полей ответа;
- символьное решение уравнений;
- автоматическое понимание свободного русского текста;
- функции и случайность внутри формул;
- HTML-разметка в условии.

## 16. Как загрузить свой файл в приложение

1. Сохраните JSON в файл, например:

   ```text
   my-tasks.json
   ```

2. Откройте приложение через HTTP/HTTPS.
3. Нажмите **«Загрузить задания»**.
4. Выберите `.json`-файл.
5. Приложение проверит структуру, выражения, зависимости и уровни.
6. При необходимости раскройте спойлер **«Предпросмотр примеров»**.
7. Если ошибок нет, нажмите **«Использовать набор»**.
8. Выберите уровень и запустите тренировку.

Плохой файл не заменяет уже работающий набор.

## 17. Рекомендуемый порядок разработки нового набора

### Шаг 1. Сформулируйте один тип упражнения

Например:

> Сложение двух однозначных положительных чисел с переходом через десяток.

### Шаг 2. Определите случайные величины

```json
"variables": {
  "a": { "min": 1, "max": 9 },
  "b": { "min": 1, "max": 9 }
}
```

### Шаг 3. Запишите вычисляемое выражение

```json
"expression": "a + b"
```

### Шаг 4. Добавьте только необходимые ограничения

```json
"constraints": ["a + b > 10"]
```

### Шаг 5. Поместите шаблон в уровень

```json
"items": [
  { "templateId": "addition-over-ten", "count": 8 }
]
```

### Шаг 6. Проверьте предпросмотр

Проверьте:

- действительно ли упражнения соответствуют замыслу;
- нет ли нежелательных крайних случаев;
- достаточно ли различных вариантов;
- правильны ли ответы;
- понятны ли отрицательные числа и скобки.

### Шаг 7. Только после этого расширяйте набор

Добавляйте следующий тип упражнения отдельным шаблоном. Не пытайтесь описывать несколько разных педагогических правил одним сложным шаблоном без необходимости.

## 18. Типовые ошибки

### Ошибка: неизвестная переменная

```json
"variables": {
  "a": { "min": 1, "max": 9 }
},
"expression": "a + b"
```

`b` нигде не объявлена.

### Ошибка: пустой пул

```json
"variables": {
  "a": { "min": 1, "max": 9 }
},
"constraints": ["a > 10"]
```

Ни одно значение не удовлетворяет условию.

### Ошибка: недостаточно вариантов

Пул содержит 5 различных условий, а уровень требует 8.

Уменьшите `count` или расширьте допустимые значения.

### Ошибка: неточное деление

```json
"expression": "a / b"
```

при произвольных `a` и `b` может давать нецелое частное.

Лучше либо:

- построить делимое через `derived`, либо
- добавить ограничение `a % b == 0` и исключить нулевой делитель.

### Ошибка: попытка использовать JavaScript

```text
Math.floor(a / b)
```

Язык шаблонов — не JavaScript.

### Ошибка: выражение в `{...}` внутри `prompt`

```text
Всего {a + b} предметов
```

Создайте:

```json
"derived": {
  "total": "a + b"
},
"prompt": "Всего {total} предметов"
```

## 19. Полный пример собственного набора

## 20. Короткая памятка

Для обычного арифметического задания почти всегда достаточно четырёх вопросов:

1. **Какие числа выбираются?** → `variables`
2. **Что вычисляется?** → `expression`
3. **Какие сочетания разрешены?** → `constraints`
4. **Сколько таких заданий нужно в уровне?** → `levels[].items[].count`

Если число должно зависеть от других чисел — используйте `derived`.

Если условие нельзя выразить одной математической формулой на экране — используйте `prompt` + `answer`.

Главный принцип: педагогическое правило должно быть явно записано в JSON и формулах, а не скрыто в программном коде.
