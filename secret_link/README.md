# ttScore — демонстратор секретной ссылки

Статический технологический демонстратор полного цикла:

1. канонический JSON встречи сериализуется в UTF-8;
2. браузер генерирует случайный 128-битный ключ и 96-битный IV;
3. JSON шифруется через AES-128-GCM;
4. создаётся бинарный файл формата `TTS1`;
5. 96-битный идентификатор имени файла вычисляется из ключа через SHA-256;
6. в URL fragment остаётся только 22-символьный ключ Base64url;
7. при открытии ссылки браузер вычисляет имя файла, загружает ciphertext, проверяет GCM-тег и отображает отчёт.

## Локальный запуск

Web Crypto и загрузка отдельного бинарного файла требуют безопасного контекста. `localhost` считается безопасным контекстом.

После распаковки архива откройте терминал в каталоге демонстратора и выполните:

```bash
python3 -m http.server 8080
```

Затем откройте:

```text
http://localhost:8080/
```

Не открывайте `index.html` напрямую через `file://`: браузер может запретить `fetch` файла из `reports/`.

## Подготовленный пример

В папке `reports/` уже находится демонстрационный ciphertext. Кнопка «Открыть пример» формирует ссылку с соответствующим ключом.

Данные примера вымышлены. Ключ примера опубликован в исходном коде и не должен применяться для настоящих отчётов.

## Проверка нового файла

После создания отчёта браузер:

- скачивает `<идентификатор>.ttscore`;
- показывает короткую секретную ссылку;
- временно сохраняет только ciphertext в `localStorage`, поэтому ссылка сразу работает в другом окне того же браузера.

Чтобы ссылка работала на другом устройстве, положите скачанный файл в `reports/` под указанным приложением именем и опубликуйте всю папку на статическом HTTPS-хостинге.

## Формат `TTS1`

```text
0..3    magic "TTS1"
4       версия контейнера: 1
5       алгоритм: 1 = AES-128-GCM
6..17   IV: 12 байт
18..N   ciphertext и 16-байтный GCM authentication tag
```

Первые 18 байт используются как AES-GCM AAD. Лимит открытого JSON в демонстраторе — 1 МиБ.

## Граница демонстрации

- это доступ по bearer-ссылке, а не аутентификация пользователя;
- любой владелец полной ссылки получает доступ;
- fragment не отправляется серверу, но может сохраниться в истории браузера, закладках, мессенджере или расширении;
- удаление файла из публичной Git-истории не гарантирует отзыв уже выданного доступа;
- демонстратор не загружает созданные файлы на GitHub автоматически.
